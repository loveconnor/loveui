# Design System Reference

Use this reference for visual direction, token choices, and anti-pattern checks.

## Direction

- Name the product type, audience, usage frequency, and emotional tone before styling.
- Choose one direction and execute it consistently. Good options include quiet SaaS, technical console, editorial product, dense operations, playful consumer, luxury/minimal, or expressive creative tool.
- Distinctive does not mean loud. The interface should feel designed for its domain, not decorated after the fact.

## Tokens

- Establish type, spacing, color, radius, borders, and elevation before assembling pages.
- Use a small spacing scale and repeat it intentionally; avoid arbitrary one-off gaps.
- Reserve large type for true heroes and major page headers. Compact panels need tighter type.
- Avoid viewport-width font sizing. Use semantic sizes and responsive layout, not fluid type tricks.
- Keep letter spacing at `0` unless there is a specific typographic reason.

## Color

- Build palettes from roles: surface, text, muted text, border, accent, success, warning, danger.
- Prefer tinted neutrals over pure gray, pure black, or pure white.
- Use accent color sparingly for meaning, not as a wallpaper.
- Avoid one-note palettes dominated by a single hue family.
- Avoid generic AI tells: purple/blue gradients, cyan-on-dark glow, glass cards everywhere, gradient text, bokeh blobs, decorative sparkles, and identical icon-card grids.

## Layout

- Create rhythm with varied spacing: tight groups, clear section breaks, and generous breathing room where the user needs scanning.
- Do not put cards inside cards. Page sections should be unframed layouts or full-width bands; cards are for repeated items, modals, or framed tools.
- Align to a real grid, then break it only for a deliberate visual emphasis.
- Keep primary product, place, object, or brand visible in the first viewport for branded or object-focused pages.

## Detail

- Icons, images, charts, and decorative elements must carry meaning or improve recognition.
- Use real product/place/person/state imagery when inspection matters.
- Use shadows and borders to clarify hierarchy; avoid generic floating panels.
- Every page should have one memorable, domain-specific design choice.
